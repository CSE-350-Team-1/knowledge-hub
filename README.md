# information-gathering

Repository to collect information. Also serves as a testbed for Github Organization features, allowing the team to hit the ground running with the class project.

## Taxonomy
- research/
  - ryan/
  - rayen/
  - nicolas/
  - austin/
  - apurva/
- README.md
- CODEOWNERS

## Update Model
- Collected information must go within one of subfolders within 'research'. The contents of these subfolders is not structured.
- Pull Requests adhere to the following requirements before approval:
  - Reviewer is required.
  - CI checks must be passed. (aspirational)
- All files and folders beside 'README.md' and 'CODEOWNERS' must adhere to kebab-case.

## Branching Rules
- The use of feature branches is mandatory. 
- All branches must come have main as the origin. 

## Ownership Model
- Ownership is strict; every team member may only make changes to their assigned files. (aspirational)

## Additional Notes
This repository is fairly limited in scope and I find many of the above rules unnecessary. However, I think this is a great way for us to get warmed up with software engineering practices and flatten the learning curve for the project itself.
